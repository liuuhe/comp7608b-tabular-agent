# 非分组相关系数的独立数值验证

v12 为已有的 `operation=correlation` 补齐独立检查。它针对声明的两个数值字段，
依次执行计划中的转换、派生与筛选，然后取两列都非缺失的记录计算非加权 Pearson r，
同时核对 `valid_count`。输入从保存的 CSV 读取，验证器使用 Python csv／math，
不执行模型代码，也不调用 pandas／NumPy 的相关系数函数。

结果仍为一个 `value`／`valid_count` 行。无完整记录、只有一对记录或任一列恒定时，
系数为 `null`，有效计数照实保留。`missing=error` 遇到任一分析字段缺失必须报错；
筛选已排除的记录不影响此判断，无关字段缺失不会删除记录。
未声明数值转换时遇到非数值／非有限输入，检查标为未覆盖，不偷偷删行。
已声明转换产生的缺失值按计划缺失规则处理。

实现先减去各列首值，再缩放和中心化，最后计算标准化向量点积。
这样保留较大偏移上的可表示微小差异，并避免极小数平方下溢。
只有相反极大数相减溢出时才先缩放；最后把舍入误差限制在[-1,1]。
判定沿用 proposal 的浮点容差 `rtol=1e-4, atol=1e-6`；有效计数必须精确，
布尔值或数字字符串不能冒充数值统计结果。

相关分析的现有结果格式没有分组字段，因此计划必须使用空的 `group_by`，
特定样本可用明确筛选。验证器不会忽略分组要求后悄悄返回总体相关。
相关系数表也不能充当散点原始数据；散点需使用单独 `raw` 分析。
分组／加权相关、任意抽样、选列是否回答用户问题和相关的因果含义都不在本次数值验证范围内。

测试同时暴露并修复了数值列表筛选的类型问题：schema 将数值列表规范化为浮点数，
原验证器把实际值和候选值转成字符串，误把2与2.0分开。
现在按数值相等判断；文本"2"仍不等于数值2，日期列表按已声明的日期类型比较。
这与 pandas 数字列的 `isin` 行为一致，未把数字文本类别自动转换成数字。

验证证据包括：

- 已知系数0.6、正负完全相关、正交样本、常量及空样本的手算例子。
- 成对缺失、无关缺失、先筛选后严格缺失规则、数值文本转换及派生字段。
- 大偏移、极小量、相反极大值，以及与独立 pandas 实现的多点交叉核对。
- 真实 Docker 中的 pandas 计算，分别核对完整样本与数值列表筛选后的系数和配对计数。
- 错误系数／计数触发计算失败，目标为代码修正，且反馈给出实际与预期差异。

全部346项测试（含真实 Docker）及 Ruff 通过。保存的 v8 D4/full 结果也做了只读重算：
`temp`与`atemp`的 r 为0.987672139039649，有效计数17379，与新验证器匹配。
原版本对此项标为未覆盖；本次诊断只证明新检查能够数值核对这份已保存结果，
不更改原状态、评分或报告，也不证明该选列适合用户的探索目的。
