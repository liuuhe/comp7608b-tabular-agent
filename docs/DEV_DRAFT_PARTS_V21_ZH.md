# v21报告片段接口与真实验证

本轮针对v19中“正确读到箱计数，但漏写引用／直接输入边界数值”的报告失败修改接口。
历史失败保持原样；本轮只做预先记录的两个报告诊断和一个完整页面流程，没有held-out推理。

## 实现与边界

`draft_contract.py`为每次真实报告调用生成动态schema。模型仍自行决定发现、文字、
引用值与支持表格；响应把文字`text`和来源`reference`分为独立片段，发现必须选择
实际支持表格。程序仅按顺序拼接、插入规范占位符，并把模型选择的片段来源加入引用。
不替模型选择结论、计算新数值、修正错误解释或代填审查结果。

来源枚举包括实际预览单元格、完整结果表极值的见证单元格、保存输出行数、问题／过滤
常量和已展示的直方图artist数值。预览外普通单元格、未展示的箱和虚构计划／profile
统计不能被选择；空表可用整表引用说明。来源存在不等于语义正确，语义审查仍必需。

文字片段禁止花括号和数字字符。JSON grammar显式排除部分数字范围，Python校验另按
Unicode类别拒绝全部numeric字符；两层范围并不完全相同。英文数字词仍可出现，不能
因此声称所有量化语义都被机械绑定。此次真实D1诊断已经展示grammar之外的数字字符
会在Python层被拒绝，不能把此接口称为可靠生成保证。

仅Ollama报告适配器更换响应格式；三条件共用。模型原始响应、parts解码结果与规范
CandidateDraft分别保存。原有grounding、renderer、审查、修正路由、预算与历史报告
读取保持兼容。旧例子转换为parts，先前报告仍以原规范格式作为修正历史。
