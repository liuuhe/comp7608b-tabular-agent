# v20：独立核对原始观测值

## 实现与结果

补齐从原始CSV到raw结果表的有限独立检查，覆盖完整数值观测和选择规则明确的排序子集。
全套493项测试（含真实Docker）及Ruff通过，较v19新增37项回归。本轮没有模型调用，
没有改变历史任务状态、正式实验配置或人工分数。最近完整三条件开发比较仍为v15；
v19真实浏览器运行的报告仍为failed。

此前验证器对raw计算直接返回uncovered，图表检查只比较保存表与artist，漏行、去重、
错配坐标后仍可通过该一致性检查。现在`reference.py`用csv/Python准备原始数据、执行
声明的转换／派生和筛选，针对直方图重建value列表，针对散点重建完整x/y配对。
只删除分析字段的缺失值，保留重复观察；missing=error在筛选之后、结果上限之前检查。
数值类型推断保留整数文本的精确值，避免先转float丢失大整数精度。

`observations.py`核对行数、字段、数值、重复次数及配对关系。没有排序要求时允许完整
输出表换序；有排序要求时核对排序键，允许同键观察换序。明确排序且边界无歧义的
limit子集从完整观测表计算。raw的group_by没有输出合同，规划验证现在直接拒绝。

沿用已有数值比较规则：整数精确，浮点relative=1e-4、absolute=1e-6；输出中的布尔值、
字符串、缺失和非有限数值不能冒充数值。浮点容差可能产生交叉候选，最多200行时用
完整二分匹配避免贪心错配。更大表的已证明一一对应仍支持；若简单对应失败且需要
超出上限的近似匹配，则标为uncovered，不猜测通过或失败。

## 有意保留的覆盖边界

- 未声明选择规则的截断／抽样仍为uncovered；不把任意样本当成源文件前几行。
- 排序limit跨越不同观察的同键边界时，需要更多排序键，否则uncovered。
- 原始非数值、日期观测以及不受支持的预处理仍为uncovered；日期用于筛选的数值图可以检查。
- 投影值相同的不同源记录不可区分。值、次数、配对匹配不能证明实际源行身份。
- 重算声明计划不能判断计划选列／筛选是否符合问题；解释、图表含义和可读性仍需审查与人工评分。

新增检查仅在full条件的原验证工具中运行，不增加工具类别、调用上限、模型调用或修正预算。
失败反馈包含少量缺失／多出观测或顺序差异，目标为代码修正，继续保留全部候选和成本。
