# v13 报告引用反馈定向验证

本轮只检查 D2、D6 的 full 条件各一次，不是新的六任务比较，也不是 held-out 结果。
补丁在固定版本 v12 的18次运行全部结束后才应用。默认开发配置未改变；本轮使用
`config/pilot-code-thinking-v12.json`，代码和审查启用 thinking，累计预算保持原样。

## 新反馈确实促成的修正

D6 的初稿报告2799、2809、857个缺失值，同时写出未保存为计算结果的百分比。
系统拒绝无已保存结果支持的比例，模型第一次修正删除了这些比例，但在三条发现中
附加了裸引用，例如 `table.missing_count_workclass.0.value`。

v13 随后明确指出这个引用位于 `finding.0`，给出
`{{table.missing_count_workclass.0.value}}` 的合法形式，并允许删除重复引用说明。
模型下一稿把三处引用都加上双花括号，成功通过报告绑定并进入独立计算／语义审查。
两次修正均复用第一次执行，没有再次计算或改写计数。

与 v12 D6/full 对照，规划、代码、初次报告、第一次修正的输入和对应输出逐一相同。
分歧发生在裸引用错误反馈：新反馈送入下一次报告调用后，模型实际改变了引用语法。
这支持“本次具体格式错误被模型修复”，不证明一般正确率或整题质量提高。
输入／输出哈希与独立计数见[归因核对](../evaluation/private/pilot-reference-feedback-v13-attribution.json)。

D2 这次首次报告就成功，没有触发新引用反馈。它与 v12 的规划输入相同，却生成了
不同的计划；后续代码和报告上下文也不同。因此，D2 的成功不能归因于该补丁。

## 仍然存在的限制

- D6 最终只报告三个字段的总体缺失数量，没有提供题目要求的类别差异，也没有具体展开
  后续分析用途。审查仍判通过；这里记录可见的覆盖不足，不代替两位评分者赋分。
- 从原始CSV独立读取48,842行，得到 workclass／occupation／native-country 的空字段数
  分别为2,799／2,809／857，与保存的表格一致。这只核对总体缺失计数，不验证探索用途。
- D2 的图表数据和柱图类型匹配未独立复核的参考，图表可读性仍需人工评分。
- v12 D3 的错误计数／均值来源解释仍是保留的语义漏检案例，本补丁没有解决该问题。
- 两个定向结果不能替换或合并进[v12完整比较](DEV_COMPARISON_V12_ZH.md)。
