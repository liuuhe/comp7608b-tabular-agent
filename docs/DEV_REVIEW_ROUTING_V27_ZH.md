# v27审查接口与确定性失败恢复

2026-11-15。承接[v26记录](DEV_STABILITY_V26_ZH.md)中的网页失败。
本轮只修审查输出字段和验证／恢复顺序，不改模型、配置、预算或评价协议。
它是定向开发验证，正式held-out、独立参考复核和人工评分仍未进行。

## 实现及边界

- 模型审查的额外问题名在JSON解码schema中只允许`plan.NAME`、`code.NAME`、
  `chart.NAME`。逐句判断与请求覆盖仍各有独立必填字段，保留原始响应和规范结果。
  不删除、搬移或自动改成通过；无效响应继续计费并保留。
  旧保存的规范`Review`接口不变。格式合法仍不能证明判断正确。
- `verify_result`先保存CSV复算、请求范围、图表、引用与窄范围陈述检查。
  存在确定性fail时，保存延期记录，直接按plan／code／report优先级进入原有修复；
  不调用语义模型，不虚计模型token，验证工具调用仍计数。
- 延期候选的逐句覆盖、请求覆盖与整体语义均为uncovered。
  修复后重新检查，无确定性失败时才运行语义审查；仍需实际审查通过才能内部通过。
  仅有uncovered不会自动跳过审查。
- 只经确定性检查的候选不成为语义检查过的所选报告。此前有完整审查记录时继续保留
  该旧候选；没有时selected_attempt为空，summary仍展示最近检出的具体问题。
  新字段last_inspected_attempt记录最近完成检查的目录；未经完整检查的候选继续警示。
  错误恢复／一次生成条件不新增验证，生成代码仍只在Docker执行。

真实调用中成功生成了合法格式；软件schema回归通过不能替代这一实测结果。

该payload含已知确定性fail；v27正常控制器会在这里跳过审查并进入计划修正。
本探针刻意直接调用审查以检查格式，属于阶段诊断，不是新的整题失败、成功恢复或准确率。
