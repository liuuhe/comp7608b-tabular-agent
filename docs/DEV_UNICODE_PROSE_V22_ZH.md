# v22报告生成的Unicode数字规则

v21的D1销售报告把年份写成阿拉伯数字字符`٢٠١١`：生成schema允许，最终Python校验拒绝。
本轮修复这个明确不一致；没有修改验证标准、报告内容选择、来源枚举、预算或研究任务。

## 修改与检查

`draft_contract.py`按当前Python的Unicode类别N生成137段字面字符范围，排除全部1,831个
numeric字符及花括号。采用字面范围，避免依赖生成引擎不一定支持的Unicode属性转义。
最终Python数字字符校验保留。模式在模块导入时生成一次，约1KB UTF-8；保存的模型
schema含完整模式，运行记录同时保存Python版本和源码，当前Unicode版本为15.0.0。

规则覆盖小数数字、罗马数字、分数、圈号、数学数字以及非BMP字符，不限制正常中文、
英文、空白或符号。旧范围曾误禁上／下标字母，现按实际数字类别处理。中文数字词和
英文数字词仍属于语义判断范围，此修改不能机械证明所有量化含义正确。

新增19项回归。补丁前9项失败、10项通过；补丁后全套528项测试（含真实Docker）及Ruff
通过。JSON传输往返后，测试逐一检查全部1,114,112个码位，确认模式与数字类别及花括号
规则一致。真实v21失败响应的离线回放也确认旧模式接受、当前模式拒绝其三处年份。
这些是规则一致性证据，不是模型任务成绩。
