# 团队复核与人工评分

系统、开发试跑和材料生成可以自动完成。Proposal 中的独立参考答案复核和双人人工评分，
需要真实团队成员完成。目前没有填写任何人工分数或复核签名。

后续命令与候选实验配置见 [正式实验交接](EXPERIMENT_HANDOFF_ZH.md)，已有结果与待补
部分见 [报告初稿](../report/DRAFT.md)。开发盲评材料分别位于
`evaluation/private/pilot-three-condition-v12-blind/` 和
`evaluation/private/pilot-reference-feedback-v13-blind/`；不同版本不合并成实验成绩。

## 正式实验前：独立复核

从 `evaluation/private/reference-review-v1/INDEX.md` 开始。这里包含六项开发任务、
30 项测试任务和 12 项变体的题目、字段说明、参考计算说明，以及完整参考表。
探索题没有唯一数值答案。

请一位没有编写参考计算的队友：

1. 对照题目与数据文档，检查筛选时间、正值/取消订单口径、分母、缺失处理、排序和单位。
2. 用自己选择的方法复算参考结果，并核对有效记录数。运行原参考脚本本身不构成独立复核。
3. 检查任务家族划分，特别是宽泛的开发探索题是否已覆盖测试题。重叠题应先调整划分。
4. 检查每题的预期交互：直接回答、终止式澄清，或澄清后回答。最后一种须预写固定回复，
   核对其确实解决歧义、且所有条件获得同样信息；不要根据测试模型输出临时编写回复。
   当前42题草稿仍全部预期直接回答，需在正式冻结前确认这一设计是否合适。
5. 在 `checklist.csv` 填写实际检查结果、姓名、日期和发现的问题；修正后重新确认哈希。
6. 完成试跑并选定配置后，按 `evaluation/private/review.template.json` 保存真实复核回执。

复核包和回执不会自动批准测试集；修改参考公式、数据或任务后需重新核对对应材料。

## 正式实验后：两位独立评分者

完整实验会产生 42 题 × 三条件 × 两次运行 = 252 份输出。盲评包保留问题、字段说明、
原始 CSV、参考表、匿名报告和图表，隐藏条件和验证日志。两人各填自己的表，先独立评分，
再处理分歧。

| 任务 | 评分内容 |
| --- | --- |
| 明确计算题 | 答案是否正确、是否满足全部要求，各 0/1 |
| 可视化 | 数据、图形类型、轴/单位/标签、可读性，各 0–2；另记明确要求是否满足 |
| 探索 | 对每个发现评正确性、证据支撑、实用性，各 0–2 |

所有输出另记因果夸大、澄清是否合理。没有实质发现的探索输出计零；尚未解决的评分分歧
不会进入最终结果。图表即使看起来漂亮，底层数据错误也不能通过。

数值引用可追溯，不代表其解释一定正确。缺失数量要与本组总记录数区别；
比较缺失率必须比较各组的“缺失数／总数”，数量最多的组未必比例最高。
相关系数还须检查字段是否回答问题、配对缺失和样本范围，不能因数值正确就接受因果解释。
这些通用核对原则不替代逐题判断，也不预先给任何实际输出打分。

`question.md`保留实际发生的澄清与回复；没有提供给模型的预写回复不会出现在材料中。
澄清合理性按实际问答判断。终止式澄清单独统计，不能当作完整分析答案通过；
要求先澄清再回答的任务，还必须满足其固定交互协议。

只把 `distribute/` 和对应评分表交给评分者；`identity_key.json` 留给汇总者。
合并脚本会保留最初的一致率和分歧记录。正式汇总需要全部运行和已解决的人工评分，
未完成时只能生成明确标注的中期结果。具体命令见 `evaluation/README.md`。
