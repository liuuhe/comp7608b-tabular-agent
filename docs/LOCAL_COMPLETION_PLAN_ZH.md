先使用现有环境。以下检查不发起模型推理：

```bash

```

doctor未就绪时按具体错误恢复服务。当前桌面Ollama使用默认`~/.ollama/models`，9B Q4
已安装，不重复下载或切回旧自定义缓存。已有模型服务时无需另起`ollama serve`。
本机Docker全局context指向未运行的OrbStack，实际执行器在Colima，故本机命令加此前缀；
其他电脑按实际引擎设置。执行镜像已存在，缺失时才运行build-executor。

```bash
# TABULAR_AGENT_CONFIG如有旧值，先取消或设为config/development.json。
DOCKER_CONTEXT=colima TABULAR_AGENT_CONFIG=config/development.json \
  uv run streamlit run app.py --server.address 127.0.0.1

# 按需验证真实Docker执行；普通测试默认跳过这些项。
mkdir -p .cache
DOCKER_CONTEXT=colima TABULAR_DOCKER_TESTS=1 uv run pytest -q \
  --basetemp=.cache/local-docker-check
```

## 10页报告的写作边界

原8,418词工作稿已存入docs/REPORT_DEVELOPMENT_HISTORY_20261116.md；report/DRAFT.md
整理为约3,050词主稿，保留方法、开发证据及正式评价待填项，尚未排成最终模板／PDF。
终稿围绕一个问题组织：在同一9B Q4模型和资源上限内，验证与有限修正能否提高单表分析
的正确性，以及为此付出的延迟／token成本。报告需要区分三件事：计算符合计划、计划符合
用户要求、解释受证据支持；v30已提供这三者可能分离的反例。

| 部分 | 目标页数 | 必须留下的内容 |
| --- | ---: | --- |
| 摘要、问题与相关工作 | 1.5 | 单表场景、三层任务、研究问题；不把已有Agent工具组合写成新算法 |
| 系统与验证方法 | 2.5 | 一张流程图、三条件区别、共享输入／事实接口、预算与验证边界 |
| 数据和评价协议 | 1.5 | 数据、题目家族、参考／评分角色、重复与失败处理、实际协议调整 |
| 结果与成本 | 2.0 | 按三层分组的结果表、token／时间；清楚标注自动数值与人工结果 |
| 错误案例与局限 | 1.5 | 日期口径、排序、报告格式、语义漏检；至少一个真实修正和一个未解决失败 |
| 结论与复现 | 0.5 | 仅回答证据支持的结论、环境／版本和代码入口 |
| 版式缓冲 | 0.5 | 为图表、标题及最终模板调整留空间 |

历史模型尝试、全部版本的测试数和逐轮流水账移到开发文档，用链接／引用指向证据；
终稿只保留理解最终设计和结果所必需的演变。正式结果尚未产生时保留待填标记；不能用
开发集数字补成held-out、独立复核或双人评分。先固定评价路线，再写正式结果与结论。
